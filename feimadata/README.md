# Feimadat · 飞常准机场大屏

根目录 `Feimadat.html` 沿用 Flightdat 的布局、配色、七机场切换、进出港筛选、搜索、分类、当日历史与详情弹窗。首页和 Flightdat 已增加入口；原 FR24 数据和采集逻辑不变。

## 已实测接通

2026-10-20，使用用户在本机安全配置的 MCP Key 完成初始化、工具发现及七机场到达/出发查询。14 个方向均成功，首轮取得并核验 **8,570 条**真实记录（包含接口返回的次日航班，不是“今日剩余”数量）。

这是一次实测，不保证后续数量相同。接口没有提供全天完整性证明，**不将返回到次日等同于全天航班全部齐全**。大屏由 `getAirportFlightBoard` 提供，注册号、机型和航司名称由 `getFlightStatus` 按航线批量补齐，不混用 FR24 记录。

- 文档：[机场实时大屏 getAirportFlightBoard](https://cmcp.variflight.com/zh/tools/#getAirportFlightBoard)。
- 接入说明：[飞常准 MCP 官网](https://cmcp.variflight.com/)。
- 官方 MCP 地址：`https://c-gw.variflight.com/chat_message/mcp/api`。
- 已公开入参：`local` 为城市/机场三字码；`out="0"` 出港、`out="1"` 进港。

`data/index.json` 是机场配置，`data/status.json` 是真实采集状态，`data/<iata>.json` 是各机场成功快照。网页按钮只重读本地快照，不调用飞常准或索取访客密钥；失败或没有成功数据时不伪造更新时间、零航班或成功提示。

## 本机配置与更新

1. 双击根目录 `配置飞常准.command`，在终端隐藏输入 MCP Key。macOS 保存到当前用户的 `Library/Application Support/Feimadat/mcp-key`，不在项目、桌面同步目录或网页根目录中；目录权限 700，文件 600。后台也支持环境变量 `VARIFLIGHT_MCP_KEY`。
2. 双击 `更新飞常准.command`。程序会先提示额度消耗；确认后最多读取七机场双向共 14 次大屏、40 次航线详情和 60 个注册号的照片元数据，有效缓存会复用。
3. 在本地 HTTP 预览中刷新 `/Feimadat.html`，或等待页面自动发现新快照。

也可在项目根目录运行 `python3 -B -m feimadata.collect --airports all`，或 `python3 -B -m feimadata.collect --airports SZX,HND`。仅依赖 Python 标准库。`--enrich-only` 仅补充已有看板；`--detail-limit 0 --photo-limit 0` 不新增详情和照片请求，仍可复用缓存。

## GitHub 每日更新

工作流 `.github/workflows/feimadata.yml`：**每天北京时间 12:00 自动运行一次**（UTC 04:00，GitHub 调度可能延迟）；当天已有采集记录时跳过自动采集，失败后不自动循环重试。**管理员点击 Run workflow 会立即执行，不受当天本地测试快照或自动运行记录限制，会使用积分。** 原 Flightdat 的更新频率不变。网页刷新只读取已保存快照，不消耗飞常准积分。

仓库 Settings → Secrets and variables → Actions 新建 `VARIFLIGHT_MCP_KEY`，值为 MCP Key 原文。不要把本机密钥文件上传到仓库、HTML、JavaScript、JSON、URL、普通变量、聊天或附件。工作流只在调用步骤注入 Secret；公开快照经过隐私检查，缓存不进入 Pages。

每日预算最多 **14 次大屏＋40 次批量详情**；一次详情可合并同一端点的多个机场（最多3个、按看板记录量控制批次），优先覆盖当前及随后时段。服务器最多预取60个注册号的图片元数据；其余注册号的照片在访客浏览器进入可见区域后并发受限地加载，**不消耗飞常准积分，不向访客暴露 MCP Key**。实际计费以账号规则为准；一次工具可能包含服务端多班详情处理，不能把请求次数当作确定账单。预算不足或源站未分配机号时仍可能缺失，Actions 摘要和页面显示真实覆盖率，不编造字段；全部普通航班补齐失败时不再冒充完整成功。

详情缓存按“航班号＋起飞日期＋起降机场＋计划起飞钟点”隔离。近起飞时30分钟刷新、其他未结束航班4小时刷新，未分配机号15分钟负缓存；每日任务仅在当天运行时检查。预算内未刷新时可保留两天内的已核验旧资料，并保留真实查询时间；不宣称是实时换机状态。缓存自动剔除过期日期。照片成功缓存30天、无照片缓存7天；换机后不会复用上一架飞机的照片。Actions Cache 跨运行保留缓存；缓存未命中时从此前已公开的已核验快照恢复资料，不依赖开发者本地隐藏目录。浏览器照片缓存独立、按注册号隔离并限制容量，服务拒绝或限流时停止，不循环重试。

## 字段与真实限制

实测返回 `structuredContent.kind="collection"` 与 `items` 数组。页面只读独立目录 `feimadata/data/`，不回退到 FR24：

- `source` 必须为 `variflight-mcp`；`airport.iata` 必须与当前选择一致。
- `generated_at` 是真实成功采集时间（Unix 秒）；`service_day` 为北京时间日期。
- `flights` 为已核验映射的航班记录数组；`today` 可提供当日累计，用于历史展开。
- `normalize.py` 将实际返回的航班号、机场、航司代码、计划/预计/实际钟点、状态、航站楼及部分彩绘资料映射为展示字段；实际时间优先于预计时间参与当前时刻计数。
- 大屏的普通航班经常没有注册号和机型；详情接口已实测 CZ5862 返回 `B30EC` / `A321-253NX`，与飞常准 App 一致。一条 CTU→SZX 详情实测返回36班（含天府扩展结果），其中31班有注册号；仅与看板的真实机场、日期、航班号、起飞钟点严格匹配，不按顺序或航班号单独关联。
- 宽体/四发属性仅由已识别的标准机型推导（例如 A330-343 不误判为 A340），不据注册号猜机型。没有可识别机型的分类显示“—”；有部分机型时仅统计已识别记录，页面明确提示覆盖不完整。货运、外航等缺少可靠字段的属性继续保持未知，不套用未经核验的枚举。
- 优先按实际注册号获取带摄影师及来源链接的 PlaneSpotters 资料照，标明“同注册号资料照片（非本航班实拍）”；服务失败时不影响航班表，保留已有源站主题图片。源站主题图标注“飞常准主题图片（非本航班实拍）”，没有署名时不编造。缺少注册号只表示未提供，不表示飞机未分配。
- “到达”是已落地；进港看板中的“起飞”表示飞行中，不是已抵达。未知状态保留原文。
- 记录 ID 是本地稳定散列，不冒充源站航班 ID。只发布已核验的航班字段，不发布原始账号信息、凭据或服务端错误正文。

大屏日期/钟点按相关机场当地时间解释；羽田使用 UTC+9，其余六机场使用 UTC+8，转换为绝对时间后统一显示北京时间。时区处理与实测 NH965 及 [ANA 官方时刻表](https://www.ana.co.jp/zh/cn/plan-book/promotions/multiple-routes-flight-resumption/)核对。预计/实际钟点跨午夜时结合计划时间及源站延误值对齐日期；源站未提供的更精确日期不补造。

与精选页不同，Feimadat 默认保留普通航班；缺少机型或彩绘标记不导致航班被过滤。保留按当前时间至当日结束计数和向上展开当日历史的交互；不假设接口必然返回全天或完整分类资料。

## 失败处理与核验

到达/出发独立处理，同日失败保留另一方向和此前已采集的当天记录；跨日先清空昨日累计，保留真实上次成功时间。预计时间延至次日时，旧的今日版本会移出今日累计。全天历史仅指本项目当天已抓到的记录，不冒充源站完整早前历史。

HTTP 401/429 停止后续请求，不反复重试；带授权请求不跟随重定向，防止转发密钥。密钥只在请求 Header 中传给官方固定地址，不进入日志、页面、快照或测试附件。

`python3 -B -m feimadata.probe --airport SZX --out 1` 只读一个看板，并将原始响应暂存于项目外的私有临时目录供核验，不直接发布猜测字段。离线回归可运行 `python3 -B -m unittest discover -s tests -p 'test_feimadata.py' -v`；页面测试为 `node tests/test_feimadat_browser.cjs`（需本机 Playwright / Chrome），测试不访问飞常准。

本地预览：在项目根目录运行 `python3 -m simulation.preview`，打开终端地址中的 `/Feimadat.html`，不要以 `file://` 打开。
