# 华南暖区暴雨模拟器：交给 ChatGPT 6.1-sol 的实施规格

版本：1.0  
整理日期：2026-10-22  
用途：作为后续编码任务的独立上下文。本文只规定设计，不包含模拟器实现。  
执行对象：ChatGPT 6.1-sol 编码模型。此名称与当前仓库的 StormSim Sol 产品、页面或分支无关。

## 1. 任务定义与优先级

开发一个无需实况输入、在用户设备上运行的华南暖区暴雨娱乐模拟器。它应生成具有合理触发、组织、移动和衰减过程的雷达演变，并在计算过程中持续展示结果。

优先级依次为：

1. 能在线推进并持续显示，界面可交互、可取消。
2. 单体移动、新生位置、冷池反馈之间具有一致的因果关系。
3. 回波和雨量来自一致的降水状态，水量有有限来源。
4. 雷达形态具有连续性、多样性和华南暖区暴雨的典型组织特征。
5. 在上述要求成立、实际性能允许时提高时空分辨率。

用户最初提出10–20公里、10分钟每步，后续明确允许提高精度。因此这些数值不是限制，不得为了遵守旧精度而降低已验证可用的配置。

### 1.1 必须满足

- 不依赖实时雷达、天气API、外部计算服务器或用户API key。
- 不等待完整过程算完再播放；第一个有效状态就绪后进入持续演变。
- 同一环境可以产生失败触发、分散对流、短时雨带或持续暴雨，不能保证每个种子都生成同一种强系统。
- 单体随引导风移动；后向传播来自上游持续新生，不能将成熟单体强制向后拉。
- 地形、海岸、环境入流和冷池影响触发；随机数不能单独决定所有天气。
- 强回波、雨强和累计雨量共用降水状态；不能分别绘制互不一致的动画。
- 记录种子、配置、模型版本和运行指标，方便开发验收与复现。
- 将性能目标、实际测量结果、气象机制依据和经验参数明确区分。

### 1.2 首版范围

包括：二维简化环境场、连续坐标单体、冷池与外流边界、残余层状降水、低层反射率、组合反射率、雨强、累计雨量、四类预设、流式播放、暂停/继续/取消、有限回放。

首版不要求：完整三维非静力动力学、逐层云微物理、实况同化、业务预报、双偏振产品、真实多普勒速度、冰雹/龙卷诊断、训练神经网络。

用户面向产品的说明使用“模拟雷达”“模拟降水”等清晰名称即可；内部实现细节放在开发文档。

## 2. 依据与建模取舍

研究结论支持以下机制，但没有直接给出一个已验证的轻量模拟器。本文的闭合公式、对象表示及参数范围是待测试的工程设计，不是论文原模型的移植。

| 必须保留的机制 | 实施含义 | 参考文献 |
|---|---|---|
| 水汽、不稳定度、抑制和局地抬升共同控制触发 | 不能只凭一个CAPE或急流阈值开始下雨 | [R1]、[R3] |
| 沿海低层入流、地形和海陆差异控制辐合位置 | 使用有位置和方向的环境场，不能只有全域“暴雨强度”滑块 | [R2]、[R5]、[R6] |
| 单体移动与对流新生共同决定系统传播 | 单体轨迹与触发边界分别计算 | [R4] |
| 冷池边界可维持连续新生，也可推进或切断入流 | 冷池内部抑制、暖侧边缘触发；强冷池不总是增强暴雨 | [R5] |
| 不同地区、时段存在不同触发路径 | 至少保留夜间沿海型、丘陵滞留型、午后局地型 | [R2]、[R6]、[R8] |
| 暖区暴雨可以有深对流和混合相贡献 | 不将全部单体强制成低顶暖云 | [R7] |
| 降水空间尺度越大，通常具有更长的结构记忆 | 雷达细节使用随流移动、按尺度变化的相关噪声 | [R9] |

“暖区”是天气系统中的位置概念，“暖雨”是微物理过程概念，二者不能混用。急流、夜间峰值、低层强回波都只能作为某类场景的特征，不能写成所有暖区暴雨的必要条件。

## 4. 模块边界与状态所有权

按职责分模块；下列名称是建议，现有工程命名可调整。

| 模块 | 输入 | 输出/职责 |
|---|---|---|
| terrain | 地形、海陆掩膜、区域投影 | 高程、坡向、海岸法向、粗糙度与局地地形触发特征 |
| scenario | 主种子、预设、参数 | 连续的入流、急流、昼夜和热湿背景强迫 |
| environment | 外部强迫、内部源汇、上一步状态 | 水汽、有效不稳定度、抑制、分层风、湿度指标 |
| initiation | 环境、地形、外流边界 | 带出生时间和原因标记的新单体事件 |
| cells | 活跃单体、环境和可用水汽 | 单体位置、几何、活跃度、凝结/降水/蒸发/脱离通量 |
| coldPools | 蒸发和下沉气流参数化源项 | 冷池内部状态、外流边界、暖侧触发候选 |
| stratiform | 单体脱离物、输送、蒸发 | 层状凝结物与地面降水通量 |
| radar | 统一降水场、单体垂直模板 | 低层与组合反射率 |
| runtime | 控制命令、固定配置 | 推进、快照、检查点、统计、取消 |
| view | 快照、播放时钟 | 地图、插值、点位、图例与回放 |

### 4.1 环境状态

环境场至少包含：

- Wv：可输送水汽储量，kg/m²。
- E_surface、E_elevated：地面/高架有效不稳定度，建议使用0–1代理量。
- I_surface、I_elevated：对应触发抑制，使用统一、明确的归一化尺度。
- RH_low、RH_mid：湿度代理，取值0–1，与场景水汽条件保持一致。
- U_bl、V_bl：边界层入流风。
- U_steer、V_steer：对流引导风。
- 较高层风或辐散诊断，用于高架触发和垂直模板。
- Ls：层状凝结物储量，kg/m²。
- 降水耗损/恢复记忆；若从已有E、冷池状态可诊断，不重复存储。
- 累计降水及水量收支诊断。

这些是降阶状态，不是假装从完整温湿廓线诊断出的实况量。首版不必展示数值CAPE；若展示等效CAPE刻度，标明其为场景代理。

### 4.2 单体状态

至少包含：稳定ID、出生时间、年龄、位置、引导速度、长短轴、方向、形状扰动状态、活跃度、生命周期状态、凝结物质量M、触发来源、父边界ID、垂直模板参数、独立随机子流。长短轴统一定义为形状核的半高全宽，单位m，避免把半径、直径与标准差混用。

单体持有M的所有权。栅格雨强是由它释放到地面的通量形成的诊断，不是另一份凝结物储库。

### 4.3 冷池状态

至少包含：稳定ID、边界折线/多边形、有效面积、深度、虚位温亏损、传播状态、形成时间和衰减状态。

可附加冷空气体积和积分热亏损，确保扩张后厚度或温差相应降低。不能把固定温差和厚度无限复制到新覆盖区。合并冷池时处理重叠区域，避免对同一区域反复叠加冷却。

## 5. 每个内部步长的更新顺序

采用明确的算子分裂，固定执行顺序：

1. 在当前时刻计算背景入流、急流、海陆风和地形风响应。
2. 输送环境水汽、能量代理及已有层状凝结物；处理开放边界。
3. 用上一子步的冷却源更新冷池和边界，计算冷池内部抑制与暖侧触发条件。
4. 计算地面和高架触发率，抽样新单体。
5. 推进单体轨迹、年龄、活跃度和几何。
6. 汇总所有单体的凝结需求，对同一水汽来源统一限额后扣账。
7. 更新单体凝结物，分配地面降水、蒸发和向层状储库的转移。
8. 更新层状降水、蒸发、能量耗损与恢复；生成下一子步冷池源项。
9. 累积降水，核对水量收支及非负性。
10. 根据已完成的核心步生成到期快照，核心步进不因快照时刻变化。输出时刻不与核心步对齐时，只读插值或输出带实际时刻的最近完成状态，不伪标时次；检查点在核心步边界保存完整可恢复状态。

冷池源项的一子步滞后属于显式耦合，不能重复应用。快照与绘制函数必须只读，不修改核心状态或推进随机数。

## 6. 环境、触发与单体算法

### 6.1 环境与边界

- 背景风由季风入流、具有轴线/宽度/末端的急流、昼夜变化及地形响应叠加形成。
- 风和热湿强迫应连续变化，不要每小时重新随机生成一张场。
- 海陆风依赖距岸距离和海岸法向，并随背景风强弱调制。
- 地形触发同时考虑迎风抬升和局地绕流/背风辐合；不要只用正坡度决定全部触发。
- 若某项辐合已包含在风场中，触发评分里不能再重复加入同一作用。
- 水汽用保正、有限体积或等价守恒输送。按实际离散方法检查CFL。
- 对入流边界使用本轮场景产生的外部水汽和能量，出流自由离开。边界输入/输出进入水量账目。
- 不使用周期边界；不能把离开区域的雨团从另一侧送回来。
- E与I允许按外部强迫恢复，但不能直接无记账地重置水汽。
- 参数或昼夜条件变化要经过有限调整时间，避免全域瞬间变色。

### 6.2 触发率

对候选面积ΔA、时间间隔Δt：

P_birth = 1 − exp(−λ × ΔA × Δt)

λ使用“个/(km²·s)”或其他明确单位，ΔA必须与其一致。建议构成：

λ = λ0 × f_moisture × f_energy × f_inhibition × f_lifting × f_recovery

各函数输出0–1；触发强迫包含低层辐合、地形、海陆边界、冷池暖侧，以及高架层的相应条件。λ0可先取1e-5个/(km²·s)，作为待调参原型值，不是观测统计值。最终要报告有效触发面积、各门控函数分布和实际新生率，防止多个门控相乘导致始终不触发。

- 地面与高架通道分开计算。不能用一个强近地冷池直接释放所有高架能量。
- 在候选格点内按真实边界/地形权重抽样连续位置。
- 使用暖侧有效面积，不把整个冷池覆盖面积当作触发面积。
- 单体之间存在能量竞争、最小间距和恢复记忆。
- 缩短时间步长或加密网格后，新生率应统计一致。
- 给每个出生事件保存主导触发原因，便于机制验收，不必默认显示给用户。

### 6.3 运动和生命周期

- 轨迹由引导风积分，建议使用二阶方法；加入小幅、有时间相关性的偏移。
- 生长取决于持续入流、可用能量、抑制和水汽供应；阶段持续时间可以随机，但不能脱离环境。
- 生命周期状态至少包括初生、生长、成熟、衰减。
- 单体死亡时，将剩余M转移到层状储库或按明确蒸发过程返回Wv，不能直接删除水量。
- 合并时质量相加、几何与强度重算；分裂时分配原有质量，不能复制M。
- 雨带方向从触发边界与单体路径产生，不写死“必须西南—东北”。
- 先实现可产生合理群体组织的规则，再考虑显式合并/分裂特效；首版允许由多个重叠单体自然连成带。

### 6.4 冷池

传播速度尺度可用：

c = κ × sqrt(2 × g × h × Δθv / θv)

它是参数化近似；κ表示摩擦等未解析影响。地面法向速度还包括环境风分量，并受地形和相邻冷池影响。[R11]

必须能够产生：

- 外流与暖湿入流相抗衡：边界缓慢移动、暖侧持续新生。
- 外流占优：边界推进、系统移动加快。
- 补给减弱或入流被冷空气覆盖：新生减少、系统衰减。

蒸发冷却同时受实际凝结物和未饱和程度限制。冷池边界本身不自动拥有强回波；无降水、无单体的冷池区域不能被填上降水颜色。

## 7. 有限水量与雨强：采用单一所有权

建议首版采用“网格持有水汽和层状凝结物；单体持有对流凝结物”的简化收支。

总大气水量：

M_atm = Σ(Wv × 格点面积) + Σ(Ls × 格点面积) + ΣM_cell

收支：

ΔM_atm + 地面降水质量
= 边界输入 − 边界输出 + 地表蒸发输入

内部凝结、脱离和蒸发只在储库间转移；内部传输不得改变总量。若以后增加外部闭合项，必须独立命名、记录，不能隐藏在“恢复”中。

实现要求：

1. 各单体先提出从入流覆盖区取水的需求。
2. 同一来源格点上所有需求合并、统一按可用量限额。
3. 扣除Wv的实际量与增加到各单体M的总量严格相等。
4. 单体释放地面降水、脱离物和蒸发水时，使用同时受限的通量分配，不能各自独立扣到负数。
5. 脱离物加入Ls；蒸发水返回Wv；地面降水加入累计量并退出大气储库。
6. 单体离开开放边界时，剩余质量计作流出。
7. 地面降水通量按面积归一化形状核分布，积分必须等于实际释放质量。
8. 雷达纹理若改变雨强分布，必须在局部重新归一化；若只代表散射差异，不得改变累计雨量。
9. 重采样使用面积权重；不允许用普通图像缩放改变总雨量。

推荐以有限转移时间控制单体释水、脱离和蒸发，并通过指数更新或保正子步避免过度扣除。雨强目标范围只用于调参和检验，不能直接钳制成一个最低暴雨强度。

能量代理和冷池是简化闭合，不宣称完整大气总能量守恒。水量账目闭合也不等于真实天气精度。

## 8. 雷达生成与视觉规则

### 8.1 基本形态

每个单体使用可变形的非对称核心、外围降水和下游残余结构。避免固定圆斑或每帧全新噪声。

- 组织层：雨带位置、走向、间断、多条平行带、整体移动。
- 单体层：增长、成熟、衰减、核心移动、相互连接。
- 纹理层：随单体/环境流移动的边缘起伏和内部细节。
- 不同尺度设置不同的相关时间；绘制频率改变不能改变噪声寿命。
- 随机纹理只细化已存在的降水/散射结构，不能在干区凭空生成强核心。[R9]

### 8.2 雨强与反射率

采用经验关系Z = aR^b；dBZ = 10 log10(Z)，Z使用mm⁶/m³、R使用mm/h。

可将下列关系作为初始配置：
- 热带降水型：a=250，b=1.2。
- 较强对流型：a=300，b=1.4。

这些是通用经验起点，未经华南场景标定；不能把其中任一关系作为全部暖区降水的真值。[R10]

- 不直接相加或平均dBZ。
- 对水平平均产品，先在线性Z空间平均再转dBZ。
- 对组合反射率，先构建诊断垂直模板再取垂直最大值；不能把水平峰值称为组合反射率。
- R=0使用明确无回波掩膜，不以log(0)或随意常数污染统计。
- 内部保留未量化场，显示色阶和传输量化不能反过来影响物理状态。
- 显示截顶只影响图例/颜色；不能无说明地截掉真实雨量。
- 点位雨强和累计量使用与地图相同的实际状态、时次和坐标。

### 8.3 诊断垂直结构

使用低层增强、深对流、衰减层状三类连续可混合模板。参数包括回波顶高、低层峰值、随高度衰减及层状增强位置。

按约5–8个诊断高度取样即可；无需求解全域三维动力学。垂直结构随生命周期、湿度和环境类型变化，不与“暖区”标签一一对应。[R7]

首版图层：
- 模拟低层反射率。
- 模拟组合反射率。
- 模拟雨强。
- 累计降水。
- 可选环境风与触发原因调试图层，默认不干扰主视图。

## 9. 起始参数与场景

以下数值均为待校准的工程先验，不得当成论文给出的统计定律：

| 参数 | 起始范围/默认建议 |
|---|---|
| 活跃单体规模 | 默认测试100–500个；另做1000个对象的负载测试 |
| 单体寿命 | 30–90分钟，受环境调制 |
| 强核心半高全宽 | 约3–10公里 |
| 引导速度 | 约5–15 m/s，场景可扩展 |
| 边界层入流峰值 | 约6–18 m/s，包含未达到明显急流的场景 |
| 低层湿度代理 | 0.80–0.95为湿润场景起点；保留更干对照 |
| 冷池虚位温亏损 | 约0.5–3 K为起始试验范围 |
| 普通强降水局地雨强 | 多数目标20–100 mm/h；由实际水量决定 |
| 极端场景局地短时雨强 | 允许100–180 mm/h，但不能通过强制增益保证达到 |
| 持续组织系统 | 约2–8小时作为场景调试目标；不保证每个种子达到 |

未观测标定的时间尺度可先从以下原型值启动：凝结转换30分钟、对流凝结物释水12分钟、向层状储库脱离30分钟、层状储库释水60分钟、能量恢复120分钟、冷池衰减120分钟。实际通量还受水汽、湿度、活跃度和局地恢复条件限制。小尺度纹理相关时间可从5–10分钟、大尺度结构从30–60分钟开始。所有值集中在版本化配置中，通过机制对照调整；不得分散成无法追踪的常数。

四个预设：

1. 粤西沿海夜间型：夜间入流增强，沿海地形与辐合触发，允许沿海组织及上游持续新生。
2. 珠三角丘陵滞留型：丘陵附近辐合与冷池外流相互作用，单体移动、雨带位置相对稳定。
3. 午后局地触发型：加热、海风和局地地形占主导，急流较弱，允许分散生消和失败触发。
4. 移动与消散型：外流增强或入流减弱，雨带加速推进、断裂或转成残余降水。

预设定义环境，不定义固定雨带轨迹或预录好的事件表。选定一种预设也不能保证整场严格符合某张示意图。

## 10. 流式运行、消息协议与复现

### 10.1 线程和更新频率

计算放在Worker或等价独立线程中，界面只负责交互与绘制。所有档位都必须流式输出。

严格区分：
- 内部积分步长。
- 雷达状态输出间隔。
- 画面刷新率。
- 模拟时间与现实时间的播放倍率。

播放倍率不能改变物理积分、随机序列或累计雨量。

### 10.2 消息类型

| 方向 | 消息 | 必要内容 |
|---|---|---|
| UI→计算 | INIT | runId、配置版本、主种子、场景、数值档位 |
| UI→计算 | START / PAUSE / RESUME / CANCEL | runId |
| UI→计算 | UPDATE_SCENARIO | runId、生效模拟时刻、参数变化 |
| 计算→UI | READY | runId、投影、域、有效配置、初始化耗时 |
| 计算→UI | SNAPSHOT | runId、seq、simTime、网格定义、产品数组、诊断 |
| 计算→UI | STATS | 实际步耗时、输出耗时、对象数、缓存占用 |
| 计算→UI | COMPLETE / CANCELLED / ERROR | runId、最终模拟时刻、状态或错误原因 |

每份SNAPSHOT必须有schemaVersion、单位、数组形状、缺测掩膜/规则和明确投影。传输缓冲与积分状态不能别名共用，防止Transferable转移导致计算数组失效。

任何过期runId的消息都必须被忽略。取消后重开不能显示旧任务晚到的回波。失败时保留已生成帧并明确显示已停止，不能伪造“完整过程”。

### 10.3 流式播放与回放

- READY后显示底图；第一份有效SNAPSHOT到达后立即进入演变。
- 维持小型播放缓冲，计算落后时降低播放推进速度或停在最新时刻。
- 允许通过已知速度插值位置和形状，但不得将未来尚未计算的生消伪装成已计算结果。
- 回放只能访问已经生成的时段；尚未生成的时间轴不可拖入。
- 缓存建议只保留最近60分钟雷达状态；更长历史按检查点和持久化设计处理。
- 暂停同时停止计算推进；回看时暂停当前推进，恢复时返回最新已算状态继续。
- 参数修改从指定时刻起影响后续演变，不改写过去帧。
- 完整检查点需包含环境、单体、冷池、累计量、随机子流状态和模型版本；两张雷达图不能代替检查点。

### 10.4 随机性

主种子派生至少四个独立流：环境初始化、触发、单体属性、视觉细节。

同一版本、同一数值配置、同一运行环境下，相同种子与操作日志应复现。更换硬件/精度可有浮点差异；更换网格只要求统计一致，不承诺逐格一致。

同配置下改变播放速度、开关图层、调整窗口、快照频率或暂停/继续，不能改变后续物理状态。核心步进应独立于输出时刻，必要时只做只读快照插值，避免输出频率改变积分序列。

## 11. 性能预算与降级规则

下列为验收目标，编码完成后必须报告实测结果，不能将其写成已达到的性能：

| 指标 | 默认档目标 |
|---|---|
| 首个有效雷达状态 | 本地运行资源就绪后2秒内 |
| 推进120秒模拟时间并输出雷达 | P95≤200 ms |
| 默认加速播放 | 争取现实1秒推进模拟10分钟 |
| UI交互/动画 | 30 fps以上 |
| 应用可归属的工作状态与缓存 | 争取≤256 MiB，运行时、底图、GPU纹理另列测量范围 |
| 默认长过程 | 24小时模拟时间，无对象/缓存持续泄漏 |

测量时：
- 写明CPU、内存、浏览器及版本、图形加速状态和网格。
- 冷启动网络/运行时加载与热启动计算分开报告。
- 计入快照构建、传输和雷达生成，不只计环境更新。
- 给出P50、P95、最大值、活动对象数和内存测量方式。
- 无法测量的浏览器内存项目标注未测，不估装成实测。

优化顺序：
1. 类型化数组、缓存复用、局部支撑核。
2. 空间索引与边界候选缓存，避免所有对象两两比较。
3. 静态地形预计算，避免每步解码地形。
4. 有条件使用GPU完成纹理与着色；保持CPU核心可测试。
5. 降低纹理细节和输出频率。
6. 降低播放倍率；如仍不足，重新初始化到较粗档位。

不能通过删除正在产雨的单体、漏算冷池、跳过水量账目或放大显示增益来“优化”。运行中自动切换物理网格会改变状态映射，首版不做；档位变化通过重开过程完成。

## 13. 验收：必须提交证据

### A. 功能与流式行为

- 完整过程尚未结束时，至少连续显示多个有效雷达状态。
- 暂停/继续/取消有效；取消后立即重开不会串帧。
- 计算慢于播放时界面保持响应，模拟时间不会凭空跳进未来。
- 四个预设都能运行，且允许部分种子出现弱过程。
- 当前点位、图层和时间标签一致。
- 30 fps动画不等同于30次物理更新；验证两者解耦。

### B. 有意义的数值不变量

- Wv、Ls、单体M和降水非负，无NaN/Infinity。
- 封闭域、关闭源汇的输送试验保持总水量。
- 开放域的输入、输出、地表蒸发和降水可核对。
- 多单体共用来源不超额取水；合并/分裂/死亡/出界不丢失或复制水量。
- 降水核积分与实际落水质量一致。
- 改变显示/快照频率、播放倍率或开关图层，不改变同配置物理结果。

水量验收建议：使用Float64累计账目。小规模Float64收支测试相对残差≤1e-6；默认Float32生产状态全程归一化残差目标≤1e-3。分母采用初始总水量加累计外部输入，报告绝对残差和该分母；如未达到，先定位来源，不静默放宽门槛。

### C. 机制对照

对每类机制用固定种子配对，并至少比较一组多个种子的汇总，避免单个随机事件决定结论：

- 更干环境/更强抑制应总体降低触发成功率和雨量。
- 改变引导风应改变单体路径；固定地形触发区不必跟着整体平移。
- 冷池维持型场景关闭冷池反馈后，边界滞留/连续新生应改变；地形仍可触发对流。
- 强化冷池应允许传播加速或入流受阻，不能只单调增强暴雨。
- 关闭地形作用应改变地形触发热点；不能要求所有场景都因此无雨。
- 有无明显急流都能存在合理过程，区别来自相应触发和补给条件。

### D. 雷达过程而非单图验收

至少展示四个场景的完整短动画或连续时次，并记录：
- 单体轨迹、寿命、移动速度。
- 强回波面积与分布。
- 雨带长宽比、滞留时间和重复经过次数。
- 5/10/30分钟间隔的空间连续性。
- 地面累计雨量与强回波持续区的对应。
- 干区无凭空强回波、无逐帧闪烁、无网格跳动、无复制圆环。

这些是形态与机制检验，不计算虚构的实况预报评分。后续如有合法获取的历史雷达序列，可离线补充统计对照；首版不依赖它。

### E. 性能和稳定性

完成默认配置6小时四场景测试、至少一次24小时稳定性测试，以及1000个对象的负载测试。报告实际吞吐、首帧、UI表现、缓存与内存趋势。未达性能目标时明确说明瓶颈与当前可用档位。

## 14. 编码执行顺序与最终交付

按以下顺序推进，每阶段产出可运行、可检查的结果：

1. 建立独立入口、Worker、控制协议和流式快照；验证不会等整轮结束才显示。
2. 实现环境与单体，建立有限水量、移动、生长和衰减；先用简单绘制检查机制。
3. 加入冷池与触发反馈，使后向新生、列车效应、传播和消散能够由规则产生。
4. 加入层状降水、垂直模板、多尺度连续纹理与统一点位数据。
5. 完成四个场景、回放和复现；做机制对照、长过程和浏览器性能测试。
6. 按实测选择默认配置；交付代码、运行说明、参数表、过程示例和验收报告。

后续编码任务授权实施后，编码模型应持续完成上述范围；不能在只完成静态雷达页面、随机色斑动画或框架搭建时结束。

最终交付报告必须区分：已实现、已测、未测、当前限制。列出真正修改的文件和启动方式，附性能测量条件；没有测过的高质量档位不能标成支持或达标。
