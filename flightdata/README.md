# Flightdat 航班精选

主站页面为根目录 `Flightdat.html`，首页菜单已添加入口。由用户提供的 `爬FR24` 整合而来，保留原有五机场、到达 / 出发、搜索、排序、历史累计、照片及署名；新增独立的宽体机统计卡、筛选按钮与航班标记，包含普通国内宽体客机。页面采用蓝灰 / 青色 / 淡紫配色，手机统计卡压缩为三列两行。

宽体展示同时修改前端筛选与采集器保留规则，宽体但没有彩绘、外航、货机等其他标记的航班不会再被过滤。“特殊机型”仍单独指四发、货机或公务机，不与宽体分类混淆。已有快照和历史不包含先前丢弃的普通宽体航班；页面可立即筛选已有宽体记录，新增覆盖需下一次成功抓取，不补造历史数据。分类可交叉，但“精选航班”总数逐条去重计算，不累加各分类。

原文件夹与其中独立的 `.git` **没有删除或改写**，已在主项目中忽略，避免上传为嵌套仓库。本目录是主项目实际使用的采集器及快照；后续请修改这里的 `scraper.py` / `config.json`，而非原导入文件夹。照片请求的联系地址已指向本项目仓库。

## 数据与更新

- `docs/data/index.json`：五机场索引。
- `docs/data/szx.json`、`pek.json`、`pvg.json`、`can.json`、`hkg.json`：页面读取的成功快照。
- `docs/data/status.json`：最近一次采集的状态；失败时不覆盖上次成功快照。
- `data/`：历史累计、彩绘注册号学习库、照片缓存。
- 根目录 `.github/workflows/flightdata.yml`：每两小时尝试采集，也可在 Actions 中手动运行“更新航班数据”。采集与保存分开，只有最后的保存任务与天气任务共享提交锁，长时间采集不会阻塞天气刷新。
- 航班工作流结束后，现有“自动更新天气数据”通过 `workflow_run` 读取主分支最新文件并发布全站。成功 / 失败状态都会发布，不新增独立 Pages 站点，也不把站点根目录改为 `/docs`。

已有快照可以直接显示，不需要先采集。页面“重新载入”只重新读取已发布的 JSON，不会替访客启动爬虫。时间统一按北京时间显示；定时任务可能延迟，源站也可能拒绝采集。数据是快照，不是实时航班保障信息，出行以机场 / 航司为准。

测试使用项目快照与离线故障样例，没有重新抓取 FR24 或触发线上工作流。

## 部分更新与源站访问失败

2026-10-19 的日志显示：深圳到达第一页取得 100 条航班，后续分页和出发看板显示 `Just a moment...` 访问验证。旧代码因出发看板失败丢弃整个机场已经取得的数据，并多次等待相同验证页面。此次失败并非 Node.js 版本警告，也不是保存任务缺少推送权限。

现按到达 / 出发独立处理：后续分页失败仍保留先前页，另一方向失败不会抹掉成功航班；当日历史仍标记为历史记录，不伪装成新采集。页面、`status.json` 与 Actions 摘要显示“部分更新”及具体失败方向。HTTP 401 / 403 / 429 或明确访问验证页面不再重复重试；一般网络错误仍按配置重试。全部失败时保留原快照与上次成功时间，但记录本轮真实错误并让工作流报错。有效的空航班列表也不会仅因 JSON 太短而被误判为拦截。

分页不再拼接第二页地址进行整页重载，而是点击当前页面实际提供的 `Later flights` 链接，让官网前端保留正常的会话、来源和 Inertia 导航头。读取该次请求返回的 JSON 或 HTML，而不是反复读取可能仍为第一页的 `#app[data-page]`。同页重复数据、错误机场、缺少航班字段都不会被当作翻页成功。

原本地启动器选择系统 Chrome，而此前整合的 CI 使用默认 Chromium headless shell。现 CI 明确安装并使用完整 Chrome，在 xvfb 窗口环境执行，不再伪装旧版 macOS Chrome/131 或修改浏览器特征。指定 Chrome 启动失败时报告实际错误，不在 CI 静默降级。此调整依据 [Playwright 浏览器说明](https://playwright.dev/python/docs/browsers)，分页响应处理依据 [Inertia 协议](https://inertiajs.com/the-protocol)。

真实 Chrome 离线回归覆盖“第一页 HTML → 第二页 Inertia JSON → 第三页 HTML”的完整流程，同时故意让初始数据岛保持不变，确认不会误读第一页；还验证第二页拒绝访问时不会伪造成功。可运行 `python tests/test_flightdata_pagination.py -v`。该文件已加入 CI 的采集前检查，上传修复时必须一并上传。

这些修复保证可用数据不会丢失、状态不会误报，**不会绕过 Cloudflare，也不保证 GitHub 托管网络可以访问全部看板**。若源站持续拒绝访问，应采用获得授权的数据接口或符合其规则的采集环境。

## 本地使用

在**项目根目录**启动现有预览：

```bash
python3 -m simulation.preview
```

将终端打印的网址路径改为 `/Flightdat.html`。不要用 `file://` 直接打开。

需要手动采集时，在项目根目录执行：

```bash
python3 -m pip install -r flightdata/requirements.txt
python3 -m playwright install chromium
python3 flightdata/scraper.py
```

采集器按自身所在目录读写，和终端当前目录无关。请遵守数据提供方的访问规则；失败时检查状态，不要将空数据伪装为新快照。上传时包括 `Flightdat.html`、整个 `flightdata/`、两份根目录工作流、首页入口及原有 `.nojekyll`，不需要上传 `爬FR24/`。
